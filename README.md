# 選択制臨床実習 希望調査・マッチングアプリ

Supabase + GitHub Pages で動く、選択制臨床実習の希望調査アプリです。

## 全体構成
- **フロントエンド**: 静的HTML/JS（GitHub Pagesで公開）
- **データベース**: Supabase（PostgreSQL）
- **認証**: 学生は個人専用URL（トークン）、管理者は簡易パスワード

## セットアップ手順

### 1. Supabaseにスキーマを作成する
1. Supabaseダッシュボード → SQL Editor を開く
2. `supabase/schema.sql` の内容を貼り付けて実行
3. `supabase/seed_data.sql` の内容を貼り付けて実行（学生100名・院内29科・院外68施設のデータが入ります）
4. 管理者パスワードを設定（SQL Editorで実行、好きなパスワードに書き換えてください）:
   ```sql
   insert into admin_settings (id, password_hash)
   values (1, crypt('ここに好きなパスワード', gen_salt('bf')));
   ```

### 2. 接続情報を確認する
`config.js` に以下が設定済みです。Supabaseダッシュボード → Settings → API の値と
一致しているか必ず確認してください：
- Project URL
- anon / publishable key（公開しても問題ない設計のキーです）

### 3. GitHub Pagesで公開する
1. このフォルダの中身（`index.html`, `admin.html`, `app.js`, `admin.js`, `style.css`, `config.js`）を
   GitHubリポジトリのルート（またはdocsフォルダ）にpush
2. リポジトリの Settings → Pages で公開ブランチ・フォルダを指定
3. 公開されたURL（例: `https://ユーザー名.github.io/リポジトリ名/`）にアクセスできることを確認

### 4. 使い方
- **管理者**: `admin.html` にアクセスしてパスワードでログイン
  - 「学生・リンク」タブで全学生分の専用URLを確認・コピー・CSV出力できます
  - 生成されたURL（`index.html?token=xxxx`）を各学生に配布してください（メール等）
  - 「ラウンド管理」タブで「第◯希望ラウンド」を作成・締切設定・切り替え
  - 「集計・抽選」タブで希望状況を確認し、締切後に「抽選を実行」で定員超過分を自動抽選
- **学生**: 配布されたURLにアクセスすると本人専用のフォームが開きます
  - 残りの必要数（院内/院外/内科系/外科系）を見ながら、空いているクールの実習先を選んで提出
  - 定員超過の場合は抽選 → 外れた場合は2次希望を提出

## 現在のスコープ（Phase 1）と今後の拡張余地
実装済み:
- 希望提出、定員表示、ラウンド管理、簡易抽選（ランダム）、2次マッチングの入口

まだ手動対応が必要な部分:
- 「学生同士の話し合い・じゃんけんでの調整」はアプリ外（口頭・掲示等）で行う想定です
- 抽選は完全ランダムです。優先順位付け等が必要な場合はロジックの追加が必要です
- 3次以降のマッチングが必要になった場合は、`attempt`列を3以上に拡張する形で対応できます

## セキュリティに関する重要な注意
このアプリはサーバー（バックエンド関数）を持たず、ブラウザから直接Supabaseへ
読み書きする構成です。管理者パスワードは「管理画面のUIを開くための簡易ロック」であり、
Supabaseへの書き込み自体を技術的に制限するものではありません
（RLSで `insert`/`update` を全許可にしているため）。
学内利用等、性善説で運用できる範囲であれば問題ありませんが、より厳密な保護が必要な場合は
Supabase Edge Functions + サービスロールキーでの実装への切り替えを検討してください。
